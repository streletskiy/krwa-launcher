# Пользовательские настройки

Начиная с лаунчера 0.1.22 обновление модпака сохраняет настройки игрока.
Обрабатываются `options.txt`, `optionsof.txt`, `optionsshaders.txt`, `servers.dat`
и текстовые конфиги модов в `config`: TOML, JSON/JSON5, CFG, CONF, INI,
properties, TXT, YAML и XML.

Первый запуск сохраняет существующие отличающиеся настройки, даже если ещё нет
истории прежних значений. После этого лаунчер запоминает контрольные суммы
опубликованных defaults. Если файл не менялся относительно прежнего default,
новая версия может обновить его. Если игрок или мод изменил файл, сохраняется
весь существующий файл. Новые отсутствующие конфиги получают defaults пака.
Файлы без MD5 из `untrackedFiles` по-прежнему устанавливаются только при отсутствии.

Перед первой подготовкой профиля и перед каждой новой версией модпака создаётся
копия существующих настроек в `<каталог игрового профиля>/.krwa-settings-backups/`.
Копии содержат исходные файлы с относительными путями и `backup.json` с версией
пака и временем. Автоматического удаления старых копий нет.
История defaults находится в `.krwa-user-settings.json` рядом с `options.txt`.
Управляемые настройки скачиваются во временную директорию, проверяются и только
затем атомарно устанавливаются. Сбой скачивания не перезаписывает прежний файл;
изменение игроком во время загрузки также сохраняется.

Обязательные файлы пака обновляются штатно: FancyMenu, Drippy Loading Screen,
Paxi/datapacks, данные квестов FTB Quests и `bcc-common.toml`. Это сохраняет
исправления меню, рецепты и проверку совместимости. JAR, библиотеки, ресурсы,
шейдеры и скрипты не относятся к пользовательским настройкам.

Для восстановления закрыть Minecraft и скопировать выбранные файлы из нужной
резервной копии по тем же относительным путям в профиль. Мир и данные авторизации
в эти копии не входят. Защита действует на перезапись лаунчером; миграции формата
настроек внутри самих модов выполняют соответствующие моды.
